# 分身层铸造

> 分身层是**认识层的投影**，不是第二次创作。本文件讲四文档的 schema、
> 怎么立公理集、以及**同源约束**。
>
> 认识层的维度与写法见 `self-schema.md`。

---

## 一、分身层与认识层的关系

| | 认识层（`SELF.md`） | 分身层（四文档） |
|---|---|---|
| 给谁看 | **你自己** | **另一个 AI** |
| 形态 | 叙事 + 骨架 + 证据 | 可执行的规则 |
| 回答 | 「我是谁」 | 「遇到 X 我会怎么做」 |
| 边界 | 存疑与缺口 | 诚实边界 + 闭包边界 |

**同一个 ground truth，两种投影。** 分身层不是另起炉灶写一份人格设定——
它的每一条都必须能从 `SELF.md` 与 `evidence/` 里指回来。

> **为什么同源是硬约束**：两份产物各写各的，就会出现「档案说你重视自由，
> 分身遇到选择却选了稳定」这种自相矛盾。用户拿到的不是两份视角，是两份互相打架的东西。

**判定**：

| 顺序 | 产物 | 判定 |
|------|------|------|
| 先有认识，再长出分身 | 可运行的人格 | ✅ 换一套骨架，分身跟着变 |
| 先定腔调，再填认知 | 一个会说话的壳子 | ❌ 语气像，但看问题的方式和谁都一样 |

## 二、四文档 schema

标题须**逐字**匹配，**唯一允许的变体是括号补注**（`_lib.heading_matches()`）——
即 `## 内在张力（至少 1 对）` 与 `## 内在张力` 等价，但 `## 内在张力测试` 不算命中。

### 2.1 `PRINCIPLES.md` —— 立场公理集（**根**）

```markdown
# 立场公理集

## 公理
| 编号 | 立场 | 理由 | 代价 | src |
|------|------|------|------|-----|
| **A1** | **不欠人情比升职重要** | 他把关系看成需要平衡的账 | 错过两次带团队的机会，且被贴上"不好合作"的标签 | SELF.md#心智模型/人情账 |
| **A2** | **…** | … | … | SELF.md#… |

## 内在张力（至少 1 对）
| 张力 | 冲突的公理 | 他自己怎么描述这个冲突 |
|------|-----------|----------------------|
| 独立 vs 被需要 | A1 vs A4 | 「我知道这样会把人推开，但我也需要有人真的需要我」 |

## 闭包边界（本质无立场的领域）
| 领域 | 为什么无立场（由哪条公理决定） |
|------|------------------------------|
| 政治立场 | 公理集里没有任何一条涉及公共事务，A1/A4 都只作用于私人关系 |

## 推演预览
**当场推**：取 A1 作用到一个档案没讨论过的情境——「同事请他做担保」→
推出「他会拒绝，且不解释太多」（档案里没有这条判断，是从 A1 推出来的）
**重构测试**：取他做过、公理集没明写的一件事——「他退出了那个合作项目」→
只用 A1 + A4 推一遍，点名用了哪两条 → 推得出来 ✅

## 信息缺口
| 缺口 | 需要什么才能补 |
|------|--------------|
| 他对"背叛"的反应没有素材 | 一次真实的被辜负经历 |
```

**形状约束（`self_check.py` 按此解析，别改）**：

- 公理表必须是 `| **A1** | **立场** | 理由 | 代价 | src |` **五列**，
  **编号与立场都要加粗**——脚本才能抽出 `(编号, 立场)` 并核对 `src`。
- `## 内在张力` 与 `## 闭包边界` 两段**必须存在**，段名照写。

### 2.2 `DECISIONS.md` —— 决策启发式

```markdown
# 决策启发式

| 场景 | 启发式（可执行的一句话） | 失效条件 | src |
|------|------------------------|---------|-----|
| 有人请他帮忙 | 先答应，再想办法 | 涉及钱或担保时他会直接拒绝 | PRINCIPLES.md#A1 |
```

**5-10 条。** 与公理集的分工：**公理是立场（怎么想），启发式是动作（怎么做）。**

**失效条件必须一起写**——只给规则不给失效条件的启发式是鸡汤不是启发式。
**失效条件通常来自「例外挖掘」**（`interview-engine.md` §二·⑤）：
你找到的每一个例外，都是这里的一行。

### 2.3 `VOICE.md` —— 表达 DNA

```markdown
# 表达 DNA

## 句式指纹
[平均句长 / 疑问句占比 / 类比密度 / 转折词偏好]

## 风格标签轴
[冷↔热 / 抽象↔具象 / 断言↔试探 / 书面↔口语，各取一值]

## 口癖与禁忌词
**口癖**（附频次）："说白了"（x23）、"你想想"（x11）
**禁忌**：从不说"赋能""闭环"这类词

## 确定性档位
[遇到不确定时他怎么表达——"我觉得"型还是"数据显示"型]

## 示例对话
[2-3 段，展示这套认知配这套说法]
```

**必须可执行、可计数。形容词一律不合格。**
内容直接取自 `SELF.md` 的 `## 表达特征`，**不重新发明**——只是换成规则形态。

**必须与心智模型相称**：一个「人情账」的人和一个「现金流优先」的人，
说话方式本来就该不同。**表达 DNA 与公理集不匹配 = 不合格。**

### 2.4 `BOUNDARIES.md` —— 诚实边界

```markdown
# 诚实边界

## 我不知道什么
[信息缺口逐条 + 每条需要什么才能补上。与 SELF.md 的存疑段一致]

## 什么会让我过期
| 判断 | 保质期 | 什么变化会让它失效 |
|------|--------|------------------|

## 闭包边界
[与 PRINCIPLES.md 的闭包边界一致]

## 遇到边界时的正确动作
[拒答 + 说明缺口，而不是硬答。给出拒答的模板句式]
```

**至少 3 条。** 这是分身层在长对话里不塌的保证：
**一个没有边界的档案，会退化成「一个说话有特点的通用助手」。**

## 三、立公理集（全流程的根）

> **无论素材多少，都先提炼出一份显式公理集。** 这是 Phase 4 的 🔴 检查点。
> **公理集立不住，后面全是白工；公理集立对了，放大是机械的。**
> **用户确认前不许放大。**

### 3.1 公理集是什么

- **3-7 条不可再分的基本立场**，写成 `PRINCIPLES.md` 的 `## 公理` 表。
- 它是分身层的 **ground truth**，也是**全流程最便宜的返工点**——
  确认检查点设在公理集上，不设在成品上。
- **它的来源是 `SELF.md` + `evidence/`**，不是模型对你的印象。
  每条公理都要能指回一条骨架条目或一处痕迹（`src` 列）。

### 3.2 七条验收标准

| 标准 | 判据 | 怎么验 |
|------|------|--------|
| **不可再分** | 每条不能用集内其他公理推出 | 试着用 A2…Ak 推出 A1：推得出 → A1 是**定理**，删掉或并入推出它的那条 |
| **有代价** | 每条都答得出「**遵守它会在什么情境下吃亏 / 什么会推翻它**」 | 答不出代价的是套话（「要重视风险」），删掉。**这是正向检验，比「不可再分」可靠得多**（§3.3） |
| **够用** | 3-7 条 | 少于 3 撑不起一个视角；多于 7 说明没提炼 |
| **互相有张力** | 至少一对公理在**极端情境**下冲突 | 一条张力都找不到 → 人格会太「顺」，推不出有棱角的判断 |
| **可推导** | 用它跑生成力探针时，能推出公理集里没写过的具体判断 | **当场推**：取一条公理作用到一个**没讨论过的具体情境**，把新判断写出来，随公理集一起交确认 |
| **可重构** | 用它**重推得回**档案里已有的判断 | **重构测试**：取一条他做过、公理集没明写的判断，只用公理集推一遍（§3.4） |
| **同源** | 每条公理的 `src` 能定位到 `SELF.md` 的具体条目 | `self_check.py` 第 11 项硬拦 |

**七条全过 → 交用户确认 → 放大。** 有一条不过 → 回 Phase 3 重新提炼，
**不要带着缺陷放大。**

> **「可推导」与「可重构」方向相反，两个都要做**：
> 前者测**解压**能走多远，后者测**压缩**有没有损。
> 只做可推导，一份漏了关键立场的公理集照样能推出一两个新判断；
> 只做可重构，一份把档案抄短的索引也能过。

### 3.3 为什么「有代价」比「不可再分」可靠

启发式要求**失效条件**（只给规则不给失效条件的启发式是鸡汤）。
公理是**比启发式更强的**主张——启发式不过是公理的复合产物。
**更强的主张反而免于举证，不成立。**

| | 「不可再分」（负向） | 「有代价」（正向） |
|---|---|---|
| 怎么判 | 试着用别的公理推出它 | 问「**遵守它，你会在哪儿吃亏**」 |
| 可靠性 | **无法机械判定，极易伪造**——靠人读 | **有具体产出**——答不出就是套话 |
| 副产品 | 无 | 代价之间必然相撞 → **张力** |

**这一列同时替代了「不可再分」与「互相有张力」两条标准的检验方式。**

> **注意这里的「你」是档案的主人，不是用户。** 问的是「他遵守这条会在哪儿吃亏」，
> 而这个答案必须来自 `SELF.md` 里**真实的代价**（他为这条放弃过什么），
> 不是你自己想出来的。

### 3.4 重构测试怎么做

1. 从 `SELF.md` 或 `evidence/` 里挑一条他**实际做过**的判断（越具体越好），
   确认**公理集没明写**它
2. 只用公理集推一遍，**点名**用了哪几条
3. 推得出来 → 压缩无损 ✅；推不出来 → **公理集漏了东西**，回 Phase 3

**重构测试的结果与「当场推」的结果一起落盘进「推演预览」段**——
它同时是保真度探针的**排除集**（这些情境已经明写了，不能拿来当留出题）。

**若档案里真实判断太少（纯访谈档、痕迹不足）**：重构对象退化为
**访谈中他说过的一条判断**，并如实标注「本档案外部痕迹薄弱，
重构测试退化为内部一致性检查」——**这不是缺陷，但不能把「自洽」读成「有根」。**

### 3.5 内在张力

**公理集必须自带至少 1 对张力**，否则人格会太「顺」——太顺的人格推不出有棱角的判断。

| 张力 | 冲突的公理 | 表现（**他自己怎么描述**这个冲突） |
|------|-----------|--------------------------------|
| **[张力名]** | A? vs A? | 「我知道 X，但我也知道 Y——我说不清那条线在哪」 |

**写法要求**：

- 张力必须**由两条真公理的冲突产生**，不能是「既严谨又灵活」这类形容词对。
- 「表现」一栏必须用**他自己的话**（引自 `CONFLICTS.md` 的对质记录），
  不是你的转述。**写不出来 → 说明公理集里缺了一条真正有代价的立场。**

**张力通常直接来自 `CONFLICTS.md` 里分类为「本质性张力」的条目**——
那些是消解不掉的价值冲突，正是公理级冲突的证据。

### 3.6 闭包边界

**本质无立场的领域**——他不会对之表态、你也不该替他表态的地方。

| 领域 | 为什么无立场（由哪条公理决定） |
|------|------------------------------|
| … | … |

**每一条都必须回指某条公理**（说明"因为公理集里没有任何一条涉及这个领域"）。
列不出的 = 通用免责声明，扣分。

**闭包边界的作用**：它是保真度探针的**排除集**——
拿一个落在闭包边界里的情境去测，测的不是保真度，是你有没有胡编。

### 3.7 🔴 确认检查点

**公理集不确认，不许放大。** 展示六段给用户：

1. **公理表**（每条带「为什么不可再分」+「遵守它的代价」）
2. **内在张力**（≥1 对）
3. **闭包边界**（各由哪条公理决定）
4. **存疑与缺口**
5. **推演预览**（当场推 + 重构测试的结果）
6. **同源声明**（每条公理回指 `SELF.md` 的哪一条）

用户觉得不对 → 回 Phase 3。**改公理集是改根，代价最小，所以这个检查点设在这里。**

## 四、同源约束（硬性）

| 约束 | 判据 |
|------|------|
| 每条公理带 `src` | 形如 `SELF.md#心智模型/<模型名>` 或 `SELF.md#核心骨架` |
| `VOICE.md` 取自 `SELF.md` 的表达特征 | 不重新发明，只换形态 |
| `BOUNDARIES.md` 的缺口与 `SELF.md` 存疑段一致 | 不能这边说有缺口、那边说没有 |
| 闭包边界在 `PRINCIPLES.md` 与 `BOUNDARIES.md` 里一致 | 两处必须同一份 |
| **分身层不得出现 `SELF.md` 与 `evidence/` 里没有的立场** | 这是**编造**，不是"合理外推" |

**最后一条是红线。** 允许的只有两种：

- **推出**：由多条公理复合而成的启发式（在 `DECISIONS.md` 里标 `src` 为公理编号）
- **无**：没有依据的，不写

**不允许**：凭「这样的人大概会怎么想」补一条。那是模型对你的印象，不是这个人。

## 五、防漂移

分身层在长对话里会逐渐滑向「一个通用的友善助手」。防线：

| 机制 | 在哪 |
|------|------|
| **反模式清单** | `DECISIONS.md` 之外，另在 `VOICE.md` 的禁忌词 + `BOUNDARIES.md` 的拒答模板 |
| **STOP 规则** | `BOUNDARIES.md`：遇到闭包边界内的领域，**直接拒答**，不绕 |
| **确定性档位** | `VOICE.md`：不规定档位，模型默认滑向模糊（"可能"、"因人而异"） |
| **边界回指** | 每次拒答都要说出「这超出档案范围，已知缺口是…」 |

**自检**：读一遍分身层，问自己——**这段话换一个人格，还成立吗？**
成立 → 这段没写出这个人，重写。

## 六、质检清单

- [ ] 公理 3-7 条，每条过了七条验收标准，且**每条带 `src`**？
- [ ] 每条公理都答得出「**遵守它会在哪儿吃亏**」？（答不出的是套话）
- [ ] 至少 1 对内在张力，且**「表现」一栏是他自己的话**？
- [ ] 闭包边界每条**回指某条公理**，不是通用免责声明？
- [ ] 「推演预览」里**当场推**与**重构测试**都做了，结果落盘？
- [ ] `DECISIONS.md` 每条带**失效条件**？失效条件来自真实的例外？
- [ ] `VOICE.md` 三项都是**可计数量化**，无形容词？
- [ ] `BOUNDARIES.md` ≥3 条，且与 `SELF.md` 存疑段一致？
- [ ] **分身层没有任何 `SELF.md` / `evidence/` 里没有的立场**？
- [ ] 读一遍问：**换一个人格，这段话还成立吗？**
