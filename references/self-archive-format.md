## 一、目录结构

档案是**用户自己拥有的一个自包含目录**，默认落在用户工作区的 `buildself/<slug>/`。

**绝不放进 skill 目录**——skill 必须自包含，档案属于用户数据（反模式 #26）。

```
buildself/<slug>/
├── README.md                    # 索引：这是什么、怎么用、版本、怎么撤回
├── SELF.md                      # ★认识层主产物（给人读）
├── CONFLICTS.md                 # ★述行冲突台账（信息量最高的一段）
├── PRINCIPLES.md                # ★分身层之根：立场公理集
├── DECISIONS.md                 # 分身层：决策启发式
├── VOICE.md                     # 分身层：表达 DNA
├── BOUNDARIES.md                # 分身层：诚实边界
├── dims/                        # 维度取证底稿（核心六维 + 扩展维度，同构）
│   ├── 01-identity.md           #   核心维度（**覆盖到才建**）
│   ├── 02-decisions.md
│   ├── 05-values.md
│   └── 07-money.md              #   扩展维度：编号 ≥07，这个人独有的领域
├── evidence/                    # 行为痕迹原始素材（只读，逐份明示同意后归集）
│   ├── chat/                    #   聊天记录导出
│   ├── calendar/                #   日历 / 日程
│   ├── transactions/            #   账单 / 消费记录
│   ├── decisions/               #   自己写过的决策备忘
│   ├── notes/                   #   笔记 / 日记 / 草稿
│   ├── others/                  #   他人对自己的描述（评价、反馈、推荐语）
│   ├── other/                   #   以上都不是
│   └── <自定义>/                #   **任意合法 slug**，如 gitlog / ledger / 学习记录
├── interview/
│   ├── round-01.md              # 访谈逐轮逐字记录
│   ├── round-02.md
│   └── LEDGER.jsonl             # 访谈台账（追加式，只增不改）
├── probes/
│   ├── P01.md                   # 探针**情境**（可见）
│   ├── P02.md
│   └── sealed/
│       ├── P01.answer.md        # 探针**答案**（哈希封存）
│       └── P02.answer.md
├── manifest.json                # 版本、哈希、变更、素材与探针索引
└── QUALITY.md                   # 独立质检评分卡
```

**各文件职责**：

| 文件 | 职责 | 谁写 |
|------|------|------|
| `README.md` | 人向索引：这份档案是什么、怎么用、当前版本、怎么撤回 | agent |
| `SELF.md` | 认识层主产物。**结构骨架 + 心智模型 + 价值排序 + 表达特征**的唯一定义处 | agent（Phase 3） |
| `dims/*.md` | **维度取证底稿**：这一维查了什么、痕迹显示什么、他说的、**还没查到什么**。`SELF.md` 的结论从这里长出来 | agent（Phase 2/3） |
| `CONFLICTS.md` | 述行冲突的**唯一定义处**（SELF.md 只写指针） | agent（Phase 3） |
| `PRINCIPLES.md` | 立场公理集，分身层的**根**；其余三份从它派生 | agent（Phase 4） |
| `DECISIONS.md` / `VOICE.md` / `BOUNDARIES.md` | 分身层三件套 | agent（Phase 4） |
| `evidence/**` | 原始素材，**只读**。agent 不得改写用户给的材料 | `evidence_ingest.py` |
| `interview/round-NN.md` | 逐字记录，**只增不改** | agent |
| `interview/LEDGER.jsonl` | 台账，**追加式** | `interview_log.py` |
| `probes/**` | 留出探针 | `probe_seal.py` |
| `manifest.json` | 索引与哈希 | 脚本 |
| `QUALITY.md` | 评分卡结果 | **独立评分 agent** |

**`SELF.md` 与 `dims/` 的分工**（别写重）：

| | `dims/*.md` | `SELF.md` |
|---|---|---|
| 是什么 | **取证的底稿**——查了什么、看到什么、还缺什么 | **合成的结论**——骨架、模型、价值排序 |
| 形态 | 按痕迹与问答组织，允许未加工 | 已提炼，每条承重 |
| 谁读 | agent（下一轮深化从这里接着做） | **用户** |
| 类比 | `distill` 的 `research/` | `distill` 的档案 |

**维度文件不是章节，是底稿。** 判据：`dims/` 里可以有「这条痕迹还解释不通」，
`SELF.md` 里不可以——那里每一条都要能承重。

**`sealed/` 是留出集。** Phase 2 / 3 / 4 的所有 agent **被明令禁读 `probes/sealed/`**；
只有评分阶段的盲测 agent 在**给出预测之后**才被允许 `probe_seal.py unseal`（反模式 #14）。

## 二、`SELF.md`

### 2.1 YAML 子集约束（重要）

frontmatter 由 `_lib.parse_frontmatter` 解析，**只支持契约限定的 YAML 子集**——
Python 标准库没有 yaml，skill 必须自包含（不引第三方依赖）。

**支持**：`key: 标量` · `key: [行内列表]` · `key: {行内映射}` · `key:` + `- 项` 块列表。

**不支持（禁止使用）**：嵌套多行映射 · 多行字符串（`|` / `>`）· 锚点别名 · 注释 ·
带冒号的未加引号标量。写了这些不会报错，会**静默解析错**——比报错更坏。

### 2.2 frontmatter 字段

```yaml
---
schema_version: 2
slug: zhang-san
title: 张三 · 自我档案
created: 2026-10-15
updated: 2026-10-15
version: 1
dimensions: [身份, 决策, 表达, 关系, 价值, 时间线, 金钱]
skeleton_count: 8
reliability: {行: 12, 述: 9, 推: 3, 疑: 4}
evidence_total: 6
interview_rounds: 5
probes_total: 4
probes_valid: 4
gaps: 长期职业取向仍未定；与原生家庭的关系只取到自述
---
```

| 字段 | 必填 | 含义与校验 |
|------|------|-----------|
| `schema_version` | ✅ | 契约版本。**高于 `SUPPORTED_SCHEMA_VERSION` 必须停止解析并提示升级**，不得猜测 |
| `slug` | ✅ | 须与目录名一致 |
| `title` | ✅ | 不加宣传性修饰（反模式 #17） |
| `created` / `updated` | ✅ | `YYYY-MM-DD` |
| `version` | ✅ | 整数，每次增量更新 +1 |
| `dimensions` | ✅ | **已建立的维度**（有 `dims/` 底稿的那些）。**核心六维在前、按契约顺序；扩展维度在后**（见 §2.5）。**没覆盖到的核心维度不写在这里，但要进 `存疑与缺口`** |
| `skeleton_count` | ✅ | 须等于 `## 核心骨架` 的**顶层条目数**（实测核对，不符即 FAIL） |
| `reliability` | ✅ | `{行: n, 述: n, 推: n, 疑: n}`。**行+述+推 = 条目总数；疑 是其中的子集，不是第四个分区**（见 §2.3）。**统计范围是全文**（`SELF.md` 正文里所有带信度标记的条目）——见下方「两个统计范围」 |
| `evidence_total` | ✅ | `manifest.evidence[]` 的长度 |
| `interview_rounds` | ✅ | 已完成的访谈轮数 |
| `probes_total` / `probes_valid` | ✅ | 封存探针总数 / 其中 `status == active` 的数量 |
| `gaps` | ✅ | 信息缺口。**没有缺口是可疑的**——写 `null` 表示未判定，不表示没有 |

> **`dimensions` 不是「六个固定格子」**——v1 时它是写死的六维，v2 起它是
> **这份档案实际建立了哪些维度**。核心六维是**默认透镜**，扩展维度是
> **这个人独有的领域**。灵活性不等于随便：声明了就必须有底稿，
> 见 §2.5 与 §8.1 第 2 项。

**未判定的字段写 `null`，不要写 `0`**。`0` 是判定结果（确实没有），
`null` 是没判——混淆会让下游把"没数"当成"数出来是零"。

**两个统计范围（别混）**：

| 范围 | 用途 | 实现 |
|------|------|------|
| **全文** | 填 `reliability` 字段；`self_check.py` 第 2 项拿它跟 frontmatter 对账 | `_lib.count_reliability(body)` |
| **核心骨架子集** | 算 `行 ≥ 30%` / `推 ≤ 20%` 两条硬指标；`self_check.py` 第 5 项 | `_lib.skeleton_reliability(body)` |

**为什么分开**：`reliability` 要描述**整份档案**的信度构成（含心智模型、价值排序等段），
而两条硬指标只管**核心骨架**——骨架是判定线的承重墙，`行` 的下限只对承重墙有意义。
`心智模型` 段里多几条 `推` 不该让骨架指标变脸。

### 2.3 信度标记写法（可机械检查）

信度轴定义见 `evidence-and-conflict.md`。**写法**在这里定义一次。

行尾一对括号，格式：

```
（<等级>[ · 疑][ · <出处指针或推导链>]）
```

- `<等级>` ∈ `行` / `述` / `推`（**证据距离轴**，三者互斥且穷尽）
- `疑` 可选，表示该条本人不确定 / 前后矛盾 / 与痕迹冲突（**正交标记，不是第四个等级**）
- 第三段可选，是出处指针（`行`/`述`）或推导链（`推`）

| 写法 | 含义 |
|------|------|
| `他连续三年拒绝管理岗（行 · evidence/decisions/2024-review.md）` | 行为痕迹佐证 |
| `他说自己最看重自由（述）` | 本人陈述，无痕迹 |
| `他对权威的抵触是选择性的（推 · 由 #3 与 #7 推出）` | 推断，须点名依据 |
| `他说不在乎钱（述 · 疑 · 但账单显示每月固定捐出 30%）` | 自述与痕迹冲突 |
| `他不太会拒绝人（述 · 疑）` | 本人自己也不确定 |

**分隔符只用 `·`（U+00B7）。** 用 `、` `,` `，` 会被判成正文括号而不是元数据——
这是刻意的严格：`（行、列都对齐）` 是正文，不该被当成信度标记。

**`（行）` 这类只写等级不写指针的写法会被接受，但列入软诊断**——没有指针就无法回查，
而回查正是溯源 S 轴测的东西。

**`（行为模式）` 不会被误判**：`行` 后面跟的是 `为` 而不是 `·`，整段按正文处理。

### 2.4 正文骨架

标题须**逐字**匹配，**唯一允许的变体是括号补注**——`## 内在张力（至少 1 对）`
与 `## 内在张力` 等价（`_lib.heading_matches()`：只放行括号 / 空白后缀，
不做任意前缀匹配，`## 内在张力测试` 不算命中）。

```markdown
# <title>

## 一句话
[一段话。这份档案的主人是谁，用他自己的坐标系，不用履历腔]

## 核心骨架
[3-10 条顶层条目。每条带信度标记。这是判定线的承重墙——
 留出探针的盲测必须能指回这里的某一条]

## 心智模型
### <模型名>
- **一句话**：他怎么看这件事
- **证据**：≥2 个不同场景（带信度标记）
- **应用**：能推出什么新判断
- **局限**：什么情况下失效

## 价值排序
**排序**：冲突时他优先牺牲哪个、保住哪个
**反模式**：他明确反对的行为与论证方式

## 表达特征
[量化。句式指纹 / 风格标签轴 / 口癖与禁忌词，三项都可计数]

## 冲突与张力
[**只写指针**：指向 CONFLICTS.md 的冲突编号，或声明「未发现述行冲突」并交代核查范围。
 冲突的唯一定义处在 CONFLICTS.md]

## 存疑与缺口
[每条 `疑` 标记的条目都必须在这里出现，或说明为什么不在]

## 变更记录
| 版本 | 日期 | 改了什么 | 触发 |
```

**硬性要求**：

- 核心骨架 **3-10 条**。少于 3 没提炼，多于 10 没取舍。
- 每条骨架条目**必须带信度标记**（`self_check.py` 第 4 项）。
- **核心骨架的 `行` 占比 ≥ 30%**。低于此，档案只是"自述誊清稿"（第 5 项）。
- **`推` 占比 ≤ 20%**。越过这条线，档案推的是蒸馏者自己（第 5 项）。
- 心智模型 3-12 条，每条须过**三重验证**（跨场景复现 / 生成力 / 排他性）。
  **上限比公理集宽**：公理要「不可再分」所以要少，心智模型是描述性的模式，可以多——
  真正的闸门是三重验证，不是条数。过不了验证的多一条都是噪声。
- 价值排序**必须给出排序**，不允许并列罗列。❌「既重视 A 又重视 B」是无信息量的写法；
  ✅「A 与 B 冲突时选 A，代价是牺牲 B」。
- `## 冲突与张力` 若声明"未发现冲突"，该声明句**≥ 20 字且须交代核查范围**
  （比对了哪些痕迹、哪几条自述）——一行「未发现冲突。」大概率是漏读。

### 2.5 `dims/*.md`（维度取证底稿）

**核心六维与扩展维度同构**——都只是 `dims/` 下的一个文件。
区分只在编号（`01-06` 是核心，`≥07` 是扩展）与来源（默认透镜 vs 这个人独有）。

```
dims/01-identity.md      # 核心：身份
dims/05-values.md        # 核心：价值
dims/07-money.md         # 扩展：金钱（为什么六维装不下它，见 §2.5.2）
```

**命名**：`NN-<slug>.md`。`NN` 两位数字，`slug` 为小写字母 / 数字 / 连字符。
编号即排序——**读的人一眼能看出哪些是通用透镜、哪些是这个人独有的**。

#### 2.5.1 文件形状（`self_check.py` 按此解析，别改）

```markdown
# 金钱

## 证据
- 2026 年 3 月拒绝了涨薪 20% 的调动，理由是「新岗位要陪客户喝酒」（行 · evidence/decisions/2026-03.md）
- 他说钱不是他考虑的主要因素（述 · interview/round-02.md）
- 但账单显示他每月固定捐出收入的 30%（行 · evidence/transactions/2026-06.csv）

## 还没查到
- 他在「自己需要用钱」和「捐出去」之间有没有做过真实取舍（可补）——需要一笔大额支出的决策
- 他面对亲人借钱会怎么反应（待事件）——只能等它真实发生
```

**两段是硬性的**：

| 段 | 要求 | 为什么 |
|----|------|--------|
| `## 证据` | **≥1 条带信度标记** | **防止维度文件写成散文**。一段读着很顺、却没有一条可回查的叙述，正是深化循环要清掉的东西（反模式 #30） |
| `## 还没查到` | **必须存在**（可为空段但要写出来） | 说不出自己缺什么 = 多半没真查。**它是深化循环的原料**（`deepening-engine.md`） |

**缺口条目末尾必须标性质**（`（可补）` / `（待事件）`）：

- `（可补）` —— 去取证 / 去问就能补上。**深化议程处理这一类。**
- `（待事件）` —— 只能等它真实发生。**不要碰，如实留着。**

> **为什么这条是硬性的**：不标性质的话，深化时会去问一个问不出真答案的问题
> （「你被背叛会怎么做」），然后把假设答案写进档案——**那是编造冒充丰富**
> （反模式 #32）。两类缺口的判据见 `deepening-engine.md` §四。

**缺口要汇总到 `SELF.md` 的 `## 存疑与缺口`。** 用户读的是 `SELF.md`——
底稿里记着缺口、用户读到的那份却没有，等于没记（`self_check.py` 第 7 项硬拦）。

#### 2.5.2 什么时候建一个新维度

**核心六维不够用时**。判据（完整版见 `self-schema.md` §二）：

> **这个领域里，有没有一个只有他才会做的选择？**

有 → 它值得一个维度。没有（比如「爱好」「性格」这种谁都能填的）→ 不建，
那是装饰（反模式 #31）。

**上限 5 个扩展维度。** 多于 5 个通常说明没提炼——领域不是越多越好，
是越「只有他才会这样」越好。

**声明**：新建扩展维度时在 `manifest.dimensions[]` 里加一条
（`id` ≥ `07`、`kind: extended`、`why`、`opened`，见 §五），
并把维度名加进 `SELF.md` frontmatter 的 `dimensions`（**核心六维之后**）。

## 三、`CONFLICTS.md`（述行冲突台账）

**冲突的唯一定义处。** SELF.md 的 `## 冲突与张力` 只写指针。

述行冲突 = 「他说的」与「他做的」对不上。**这是档案里信息量最高的条目**
（判定线：一致之处复述即可，冲突之处只有真懂了才预测得准）。**禁止抹平**（铁律 2）。

```markdown
# 述行冲突台账

## C1 · <一句话概括冲突>
- **述**：他说…（述 · interview/round-02.md）
- **行**：痕迹显示…（行 · evidence/calendar/2026-09.md）
- **分类**：本质性张力 | 领域性张力 | 时间性张力 | 未解决
- **对质**：怎么问的、他怎么答的
- **回应类型**：承认 | 条件差异 | 质疑痕迹 | 回避
- **处置**：进价值排序 / 写成条件的边界 / 已回查痕迹（结论：…） / 保留为未解决张力

## 未发现述行冲突
[若确实核查过而无冲突：写清比对了**哪些痕迹**与**哪几条自述**、为何不构成冲突。
 判据：一个不熟悉他的人，能否据此复核这次核查？]
```

**四类分类**（判据见 `evidence-and-conflict.md`）：

| 分类 | 含义 |
|------|------|
| **本质性张力** | 消解不掉的价值冲突。**生成力主产地**，进价值排序 |
| **领域性张力** | 补全语境能消解的——揭示「条件的边界」 |
| **时间性张力** | 立场随时间改变。**演化轨迹本身是资产**，标注「已被 X 修正」而非删除 |
| **未解决** | 用户回避或答不上来。**仍保留**，不因回避就抹平 |

**禁止**：否认对立式调和（「其实两者并不冲突」「本质上是统一的」）。
判据是**信息量净减少**，不是句式——「虽然…但是…」本身合法，它是描述张力的正确写法。

## 四、分身层四文档

分身层的**根是 `PRINCIPLES.md`**（立场公理集），其余三份从它派生。
**四份必须同源**：每条公理都能回指 `SELF.md` 的具体条目（`self_check.py` 第 11 项）。

> 为什么是四份文档而不是一个可安装的 skill：产物是**用户自己拥有的档案**，
> 应能被整组喂给任何 AI，而不绑定某个工具。日后若要包成 skill 是平凡的一步。

### 4.1 `PRINCIPLES.md` —— 立场公理集（根）

```markdown
# 立场公理集

## 公理
| 编号 | 立场 | 理由 | 代价 | src |
|------|------|------|------|-----|
| **A1** | **<不可再分的一句话>** | 为什么他会这么想 | 遵守它会在什么情境下让他吃亏 | SELF.md#心智模型/<模型名> |

## 内在张力（至少 1 对）
| 张力 | 冲突的公理 | 他自己怎么描述这个冲突 |
|------|-----------|----------------------|

## 闭包边界（本质无立场的领域）
| 领域 | 为什么无立场（由哪条公理决定） |
|------|------------------------------|

## 推演预览
[当场推：取一条公理作用到一个档案没讨论过的具体情境，写出新判断
 重构测试：取一条他做过、公理集没明写的判断，只用公理集推一遍，点名用了哪几条]

## 信息缺口
[该有而没给的——需要时先查或回用户补]
```

**形状约束（`self_check.py` 按此解析，别改）**：公理表必须是 `| **A1** | **立场** | 理由 | 代价 | src |` 五列，
**编号与立场都要加粗**；「闭包边界」「推演预览」两段必须存在且段名照写。

**验收标准**（完整判据见 `portrait-forge.md`）：3-7 条 · 不可再分 · **有代价**（正向检验，比"不可再分"可靠）·
够用 · **互相有张力（≥1 对）** · 可推导 · 可重构 · 每条带 `src`。

### 4.2 `DECISIONS.md` —— 决策启发式

```markdown
# 决策启发式

| 场景 | 启发式（可执行的一句话） | 失效条件 | src |
|------|------------------------|---------|-----|
| 遇到 X 时 | 做 Y | 什么情况下这条不适用 | PRINCIPLES.md#A2 |
```

5-10 条。**失效条件必须一起写**——只给规则不给失效条件的启发式是鸡汤不是启发式。

### 4.3 `VOICE.md` —— 表达 DNA

```markdown
# 表达 DNA

## 句式指纹
[可计数：平均句长 / 疑问句占比 / 类比密度 / 转折词偏好]

## 风格标签轴
[冷↔热 / 抽象↔具象 / 断言↔试探 / 书面↔口语，各取一值]

## 口癖与禁忌词
**口癖**（各附频次）：…
**禁忌**：…（他从不使用的词）

## 确定性档位
[遇到不确定时他怎么表达——"我觉得"型还是"数据显示"型]

## 示例对话
[2-3 段，展示这套认知配这套说法]
```

**必须可执行、可计数。形容词一律不合格**（不可证伪的描述，反模式 #3 的同族）。
❌「语言犀利，善用类比，富有幽默感」 ✅「短断言句为主；类比密度高；高频使用『反过来想』式倒置」。

**表达 DNA 必须与心智模型相称**：一个「逆向思考、能力圈」的人和一个「现金流不会说谎」的人，
说话方式本来就该不同。先有认知再长出表达；先定腔调再填认知 = 一个会说话的壳子。

### 4.4 `BOUNDARIES.md` —— 诚实边界

```markdown
# 诚实边界

## 我不知道什么
[信息缺口逐条 + 每条需要什么才能补上]

## 什么会让我过期
[每条判断的保质期，什么变化会让它失效]

## 闭包边界
[本质无立场的领域——与 PRINCIPLES.md 的闭包边界一致]

## 遇到边界时的正确动作
[拒答 + 说明缺口，而不是硬答]
```

**至少 3 条**。这是分身层在长对话里不塌的保证：一个没有边界的档案会退化成
「一个说话有特点的通用助手」。

## 五、`manifest.json`

```json
{
  "schema_version": 2,
  "slug": "zhang-san",
  "created": "2026-10-15",
  "updated": "2026-10-15",
  "version": 1,
  "self_sha256": "<64 位小写十六进制>",
  "principles_sha256": "<64 位小写十六进制>",
  "interview_rounds": 5,
  "dimensions": [
    {"id": "01", "name": "身份", "kind": "core"},
    {"id": "02", "name": "决策", "kind": "core"},
    {"id": "05", "name": "价值", "kind": "core"},
    {"id": "07", "name": "金钱", "kind": "extended", "file": "07-money.md",
     "why": "C1 与存疑段都指向钱：他对钱的自述与账单对不上，六维里装不下",
     "opened": "2026-10-15"}
  ],
  "evidence": [
    {
      "id": "E001",
      "path": "evidence/chat/wechat-2024.md",
      "type": "chat",
      "title": "2024 年微信导出",
      "words": 12000,
      "sha256": "<64 位>",
      "added": "2026-10-15",
      "consent_at": "2026-10-15T14:03:00",
      "dimensions": ["决策", "关系"],
      "reliability": null
    }
  ],
  "probes": [
    {
      "id": "P01",
      "situation_file": "probes/P01.md",
      "sealed_file": "probes/sealed/P01.answer.md",
      "sealed_sha256": "<64 位>",
      "frozen_at": "2026-10-15T14:10:00",
      "status": "active"
    }
  ],
  "changes": [
    {"version": 1, "date": "2026-10-15", "note": "建档"}
  ]
}
```

**字段纪律**：

- `self_sha256` / `principles_sha256` **由 `self_seal.py` 写入，不要手抄**（反模式 #28）。
  档案一改，哈希就过期，`self_check.py` 会当硬性 FAIL 拦截。
- `probes[].status` ∈ `active` / `contaminated`。**`contaminated` 的探针不计入保真度 G 的分母**。
- `evidence[].dimensions` / `reliability` 脚本判不出（那是语义判断），**写 `null` 由 agent 回填**
  （反模式 #27：让脚本做语义判定）。
- `evidence[].type` **默认七类，但接受自定义**——`gitlog` / `ledger` / 任何合法
  slug（小写字母开头、只含小写字母/数字/连字符）。每个人的痕迹长得不一样。
- `dimensions[]` 是**维度的声明表**。核心维度只需 `{id, name, kind: "core"}`；
  **扩展维度必须多带 `file` + `why` + `opened`**——`why` 答不出就不该建（反模式 #31）。
- `changes` 追加式，**只增不改**。
- `consent_at` 是逐份明示同意的时间戳。**没有它意味着这份材料不该在这里**。

## 六、`probes/`（留出探针）

留出探针是判定线可信的**机械保证**（铁律 3）。

**探针 = 一件他真实做过的事**，拆成两半落盘：

| 文件 | 内容 | 可见性 |
|------|------|--------|
| `probes/P01.md` | **只写情境**：「当时面对什么选择，有哪些选项」 | Phase 2/3/4 可见 |
| `probes/sealed/P01.answer.md` | **决定 + 当时的理由** | **Phase 2/3/4 禁读** |

**情境必须干净**：不得出现决定本身、不得出现暗示性理由（反模式 #15）。
「他最后选了 B，因为…」写在情境里，探针就废了。

**冻结纪律**：

- `freeze` 一旦落盘，情境与答案**不可改**。要改必须 `unfreeze` 并留痕。
- `verify` 校验 `sealed_sha256` 未被篡改，供 `self_check.py` 第 10 项调用。
- **后出题等于让写档案的人自己挑考题**（反模式 #6）。探针必须在 Phase 1 冻结，
  早于 Phase 2 的访谈。
- **访谈中主动回避封存的探针决定**。若用户主动提起，记 `probe_contamination: true`，
  该探针标 `contaminated`（反模式 #14）。

**条数**：标准档 3-5 条 · 快速档 3 条 · 深度档 5 条。
**少于 3 条时保真度 G 不给分**，标「留出集不足，保真度未验证」，等级封顶 C。

## 七、`QUALITY.md`

由**独立评分 agent** 写，不由访谈 agent 写（反模式 #18）。

```markdown
# 质检评分卡

> 评分 agent：<标识> · 评分时间：<ISO 时间>
> 被评档案：SELF.md @ <self_sha256 前 12 位>

## 保真度 G（/30）
[每条探针：情境 / 预测 / 真实决定 / 方向命中 / 依据承重 / 反事实敏感性]
命中率：<n>/<有效探针数> = <x>%

## 诚实度 H（/25）
[冲突记录完整度 / 对质质量]

## 可执行性 X（/20）
[公理集 3-7 条+代价 / 张力 / 闭包边界回指 / 运行规则齐备]

## 溯源 S（/25）
[断言 diff 抽查 6 条的结果 / 缺口映射 / 同源]

## 结论
总分：<n>/100 · 等级：<A|B|C|D>
覆盖等级：<稀疏|标准|丰富|饱和>（**标签，不计入总分**——见 self-scorecard.md §零）
红线触发：<无 | G<12 | X<8 | H=0 | S=0 | 探针<3>
```

**若环境无法 spawn 独立 agent**：顶部写「**本档案未经独立评分**」，**不给等级**，
不写 `EVALS.jsonl`。宁可没有分数，也不要一个冒充独立评分的自评分。

```bash
python3 scripts/self_seal.py buildself/<slug> --check    # 校验是否过期

```

### 8.1 十二项结构检查（`self_check.py`）

| # | 检查 |
|---|------|
| 1 | frontmatter 完整性（必填字段齐备 + `schema_version` 受支持） |
| 2 | frontmatter 交叉校验（slug 与目录名 / **维度三方对账：`dimensions` ↔ `dims/` ↔ `manifest.dimensions[]`** / `reliability` 形状 / 日期形态 / `skeleton_count` 与实测一致） |
| 3 | 核心骨架 3-10 条 |
| 4 | 每条骨架条目带信度标记**且**带出处指针 |
| 5 | `推 ≤ 20%` 且 核心骨架 `行 ≥ 30%` |
| 6 | `CONFLICTS.md` 存在；冲突已分类，或显式声明"未发现"且交代核查范围；**无否认对立式调和** |
| 7 | 存疑段非空，`疑` 条目都在此出现，**且各维度底稿的缺口已汇总到此** |
| 8 | `evidence/` 非空（档案必须有行为痕迹依据） |
| 9 | `interview/` 非空且 `LEDGER.jsonl` 存在 |
| 10 | 探针 3-5 条，且 `verify` 通过（封存未被篡改） |
| 11 | 分身层每条公理都能回指 `SELF.md` 条目 |
| 12 | `manifest` 契约字段齐备 + 两个哈希已封存且未过期 |

**第 2 项的维度对账**（v2 新增）——灵活性不能变成「随便写」：

| 判据 | 为什么 |
|------|--------|
| 每个声明的维度都有非空的 `dims/NN-slug.md` | 声明了却没底稿 = 名义覆盖 |
| 维度文件的 H1 标题 == 声明的维度名 | 文件与声明对不上，下游按名字找不到 |
| 文件 `## 证据` 段 ≥1 条带信度标记 | 防止维度文件写成散文（反模式 #30） |
| 文件 `## 还没查到` 段存在 | 说不出自己缺什么 = 多半没真查 |
| 核心六维按契约顺序、且都在扩展维度之前 | 编号即排序 |
| 扩展维度在 `manifest.dimensions[]` 里声明了 `why` + `opened` | 扩展维度要**有理由**（反模式 #31） |
| `evidence[].dimensions` 的取值 ⊆ 声明的维度 | 悬空归类 |

### 8.2 改动纪律（工程类反模式的家）

**#26** 塞进 skill 目录 · **#27** 让脚本做语义判定 · **#28** 手抄哈希 · **#29** 改完不重新封存。
**#30** 为丰富度灌水 · **#31** 把扩展维度当装饰 · **#32** 深化时硬答「待事件」缺口
（后三条见 `deepening-engine.md` §八）。

**契约同步**：改字段名 / 枚举 / 目录名 / 检查规则**必须同时改**本文件与 `scripts/_lib.py`。
`_lib.sha256_file` 的算法是契约的一部分，**不要动**。

## 九、最小合法示例

一个能过 12 项结构检查的最小档案见 `examples/minimal-self/`。
它故意做得**薄但合法**——用来对照"哪些是结构要求、哪些是质量要求"：

> **过了 12 项结构检查 ≠ 质量合格。** 结构检查拦的是**结构缺陷**，不是内容真伪。
> 一份字段齐全、标记规范的档案完全可能是编造的。过了只等于「没有结构性缺陷，
> 值得花一次评分」，绝不能代替评分卡。
