# 质检评分卡（四轴）

> **铁律：访谈 agent 与评分 agent 必须是两个独立 agent，绝不自评。**
> LLM 自评接近随机水平，自评等于没评。
>
> **做不到独立评分就不评分**——标注「未经独立评分」且**不给等级**（§九）。

---

## 零、四个轴，四个数

| 轴 | 分值 | 测什么 | 不达标的产物是 |
|----|------|--------|--------------|
| **保真度 G** | **30** | 拿档案预测留出探针的真实决定，命中吗（**判定线**） | **自述誊清稿**——读着像，但预测不了你 |
| **诚实度 H** | **25** | 述行冲突是否如实记录而非抹平 | **美化过的自己** |
| **可执行性 X** | **20** | 分身层的公理集是否真可运行 | **一段漂亮话** |
| **溯源 S** | **25** | 每条断言能否指回 `evidence/` 或 `interview/` | **编造者** |

**四轴不合并、不相加、不互相补偿。** 分开报。
「保真度低但诚实度高」不是 15 分的轴加 20 分的轴，是**两个必须分别说的信号**。

**顺序就是权重**：G 最高，因为它是判定线——其余三轴测「多忠实地搬了素材」，
只有它测「能不能预测你」。

### 0.1 覆盖等级：一个**标签**，不是一个轴

`self_gaps.py` 另外报一个**覆盖等级**，写在 `QUALITY.md` 的结论里：

| 等级 | 判据 |
|------|------|
| **稀疏** | 核心六维没建齐，或痕迹 < 3 份 |
| **标准** | 核心六维都建了，且痕迹 ≥ 3 份 |
| **丰富** | 核心六维全建且每维 ≥3 条；痕迹 ≥6 份 / ≥4 类；有扩展维度；心智模型 ≥5；冲突 ≥2 |
| **饱和** | 丰富 + **已无可补缺口**（剩下的全是「待事件」） |

**为什么它不计入 100 分**——这是刻意的：

> **丰富度是唯一可以靠灌水刷上去的指标。**
> 保真度灌不了（要预测对），诚实度灌不了（要如实记冲突），
> 溯源灌不了（要能回查），**只有「资料多少」能靠堆**。
>
> 所以它**不进分母**。它只回答一个问题：**下一轮该不该继续深化。**
> 把它算进总分，等于给灌水开了一条计分通道。

**「丰富」和「饱和」的区别**：丰富是「资料多」，饱和是「**能问的都问完了**」。
前者靠堆，后者只能靠真问——所以饱和是深化循环的停止条件（`deepening-engine.md` §七），
不是一个可以刷的成就。**一份饱和的档案仍然有存疑段，只是里面全是「待事件」。**

**它只升不降是错的**：如果深化时把某个维度的底稿改薄了，等级就该降。
**等级是当前状态，不是历史最高分。**

## 一、保真度 G（30）—— 判定线

### 1.1 出题（Phase 1 冻结，先于档案）

3-5 条**真实决定**。每条拆两半落盘：

- `probes/P0X.md` —— **只写情境**（当时面对什么选择，有哪些选项）
- `probes/sealed/P0X.answer.md` —— **决定 + 当时的理由**（哈希封存）

**出题纪律**：

| 纪律 | 为什么 |
|------|--------|
| 题目**先于档案存在** | Phase 5 才出题 = 让写档案的人自己挑考题，分数虚高 |
| 题目来自**真实往事**，不是假设 | 假设题测的是「他怎么说」，真实往事测的是「他怎么做」 |
| 情境**不含决定、不含暗示性理由** | 泄露了就不是留出集（反模式 #15） |
| **访谈中不讨论**这几条 | 讨论了档案就「见过」答案（反模式 #14） |
| 排除「推演预览」里已明写的情境 | 那些已经写进档案了，不能当留出题 |

### 1.2 答题

**盲测 agent 只读 `SELF.md` + 分身层四文档，禁读 `probes/sealed/`。**

对每条情境：

1. 预测「这个人会怎么决定」
2. **必须说出依据的是哪条骨架条目 / 哪条公理**——指不回去的预测，即使蒙对也拿不到依据分

### 1.3 打分（每条探针 0-10）

| 判据 | 分 | 满分条件 | 零分条件 |
|------|----|---------|---------|
| **方向命中** | 0-6 | 预测方向与真实决定一致（6） | 相反或回避（0）；方向模糊（3） |
| **依据承重** | 0-4 | 指回具体条目，**且取反该条目预测会改向**（4） | 指回但取反不改向（2）；指不回（0） |

```
G = round( Σ(每条得分) / (有效探针数 × 10) × 30 )
```

**命中率**（单独报，不并入 G）：命中 = 方向命中 **≥3** 分。

```
hit_rate = 命中数 / 有效探针数
```

**`contaminated` 探针不计入分母**（访谈中被讨论过的那些，见 `manifest.probes[].status`）。

### 1.4 反作弊：反事实敏感性

**「指回某条」可能是事后贴的标签。** 评分 agent 必须验证：

> 取探针回答里点名的条目，问：**把它取反，预测会变吗？**

- 变 → 点名是真的（给满分 4）
- 不变 → 点名是事后贴的标签（给 0-2）

这条对应 `PRINCIPLES.md` 的「可推导」与「可重构」——
**一个真正承重的条目，取反它一定会改变结论。**

### 1.5 不达标怎么办

`G < 12` → **等级封顶 C**。判定线没过，其余三轴再漂亮也还不是成品。

**不要靠加长正文刷分**——保真度测的是预测力，灌水只会稀释。
回 Phase 2/3 **补取证**（去要痕迹、去问具体事件），迭代上限 2 轮。

**探针 < 3 条时 G 不给分**，标「留出集不足，保真度未验证」，等级封顶 C。

## 二、诚实度 H（25）—— 铁律 2

| 检查项 | 分 | 判据 |
|--------|----|------|
| **冲突记录完整度** | 15 | 访谈中检测到的**每一处**述行冲突都在 `CONFLICTS.md` 如实记录，**两侧俱全**（有「述」侧也有「行」侧）。按比例给分 |
| **对质质量** | 10 | 每处冲突都有对质记录（用户回应 + 处置：承认 / 条件差异 / 质疑痕迹 / 回避）。按比例给分 |

**红线**：出现**否认对立式抹平**（「其实两者并不冲突」「本质上是统一的」）→
**H = 0，等级封顶 C**。检测由 `self_check.py` 第 6 项机械执行（已剥引号与否定提及）。

**「无冲突」情形**（确实核查过而无述行冲突）：
按**核查记录质量**给 15-25——

| 写法 | 分 |
|------|----|
| 指名比对了**哪些痕迹 / 哪几条自述**，并说明为何不构成冲突 | 高 |
| 只有一句「未发现冲突」（<20 字） | 低 |

判据：**一个不熟悉他的人，能否据此复核这次核查？**

**注意「回避」不等于「无冲突」**：用户回避的对质仍要记录为「未解决张力」。
把回避记成「无冲突」= 抹平。

## 三、可执行性 X（20）—— 分身层

| 检查项 | 分 | 判据 |
|--------|----|------|
| 公理集 3-7 条，每条带「为什么不可再分」+「**遵守它的代价**」 | 8 | 答不出代价的条目是套话，不计分 |
| ≥1 对**内在张力**（由两条真公理冲突产生，非形容词对） | 4 | 「表现」一栏须是**他自己的话**，不是转述 |
| 闭包边界每条**回指某条公理** | 4 | 列不出的 = 通用免责声明，扣分 |
| 运行规则齐备：STOP / 拒答模板 / 表达 DNA 量化 / 反模式 ≥5 条 | 4 | — |

**红线**：`X < 8` → 等级封顶 C。

**这一轴测的是**：把分身层单独交给一个 AI，它能不能**真的运行起来**，
而不是读起来像一份人格分析报告。

## 四、溯源 S（25）

| 检查项 | 分 | 判据 |
|--------|----|------|
| **断言 diff** | 18 | 随机抽 **6 条**实质断言，回 `evidence/` 或 `interview/` 找对应 |
| **缺口映射 + 同源** | 7 | `SELF.md` 的存疑条目逐条在冲突段出现；分身层公理逐条回指 `SELF.md` |

**断言 diff 的四种结果**：

| 结果 | 分 |
|------|----|
| 可定位（找得到对应痕迹/轮次） | 3 |
| 标 `推` 且**点名**了推导链 | 2 |
| 标 `推` 但**点不出名字**（假推断） | **0** |
| 无对应却以**确定口吻**陈述（编造） | **0** |

**红线**：`S = 0`（存在编造或假推断）→ **直接判 D**，不论总分。

> **为什么假推断按编造处理**：标了「推」却点不出依据，和没标是同一种东西——
> 它用「推断」这个标签换取了「不必举证」的待遇。**更强的主张反而免于举证，不成立。**

## 五、等级与红线

| 等级 | 分数 | 含义 |
|------|------|------|
| **A** | ≥85 | 出厂即精品 |
| **B** | 70-84 | 合格 |
| **C** | 55-69 | 能用但需谨慎，**冲突段与存疑段必读** |
| **D** | <55 | 不建议使用 |

**红线汇总**（触发任一即按规则处置）：

| 触发 | 处置 |
|------|------|
| `G < 12` | 封顶 C |
| `X < 8` | 封顶 C |
| `H = 0`（抹平） | 封顶 C |
| `S = 0`（编造/假推断） | **判 D**，不论总分 |
| 探针 < 3 条 | G 不给分，封顶 C，标「保真度未验证」 |

## 六、执行流程

```
1. 结构自检      python3 scripts/self_check.py <档案>      # 12 项，机械
2. 探针盲测      独立 agent（禁读 probes/sealed/）→ 预测 + 点名依据
3. 反作弊        取反点名的条目，验证预测是否改向
4. 对答案        读 probes/sealed/，逐条打 方向命中 + 依据承重
5. 抽断言 diff   随机 6 条回查 evidence/ 与 interview/
6. 核冲突        对 CONFLICTS.md 与访谈台账，算 H
7. 核分身层      对 PRINCIPLES.md，算 X
8. 报覆盖等级    python3 scripts/self_gaps.py <档案>        # 标签，不进总分
9. 出分          QUALITY.md + （可选）EVALS.jsonl
```

**第 8 步只抄等级，不抄议程**——议程是 Phase 7 深化循环的输入，
不是评分的一部分。评分说「这份档案现在值多少」，议程说「下一轮该补什么」。

**第 2 步与第 4 步必须是不同的 agent 上下文**——同一个 agent 先预测后对答案，
它会不自觉地往答案上凑。

## 七、结果格式（`QUALITY.md`）

```markdown
# 质检评分卡

> 评分 agent：<标识> · 评分时间：<ISO 时间>
> 被评档案：SELF.md @ <self_sha256 前 12 位>

## 保真度 G（/30）
| 探针 | 情境 | 预测 | 真实决定 | 方向命中 | 依据承重 | 反事实敏感 |
|------|------|------|---------|---------|---------|-----------|
| P01 | … | … | … | 6/6 | 4/4 | 是 |

命中率：<n>/<有效探针数> = <x>%
得分：<n>/30

## 诚实度 H（/25）
冲突记录完整度：<n>/15 —— <说明>
对质质量：<n>/10 —— <说明>
抹平检测：无 / 有（<命中片段>）

## 可执行性 X（/20）
公理集：<n>/8 —— <条数、代价是否齐备>
内在张力：<n>/4
闭包边界：<n>/4
运行规则：<n>/4

## 溯源 S（/25）
断言 diff（抽 6 条）：可定位 <a> · 推断点名 <b> · 假推断 <c> · 编造 <d>
缺口映射 + 同源：<n>/7

## 结论
总分：<n>/100 · 等级：<A|B|C|D>
覆盖等级：<稀疏|标准|丰富|饱和>（**标签，不计入总分**——§0.1）
红线触发：<无 | G<12 | X<8 | H=0 | S=0 | 探针<3>
建议：<回 Phase 2/3 补取证的具体动作>
```

**「总分」与「覆盖等级」必须分开写两行**，别把覆盖等级塞进分数栏——
一个是「这份档案准不准」，一个是「这份档案厚不厚」。**两份不同的判断。**

## 八、反作弊清单

| 作弊形态 | 检测 |
|---------|------|
| 探针先于档案？ | 查 `manifest.probes[].frozen_at` 是否早于 `SELF.md` 的 `created`/`updated` |
| 探针被讨论过？ | 查 `LEDGER.jsonl` 的 `probe_contamination`；污染的不计分 |
| 点名是事后贴的？ | **反事实敏感性**（§1.4） |
| 自报数字好看？ | **数字只作索引，不作得分依据**——评分 agent 必须打开 `evidence/` 与 `interview/` 实核 |
| 冲突被悄悄删了？ | 比对 `LEDGER.jsonl` 的 `contradicts` 条数与 `CONFLICTS.md` 的条目数 |
| 加长正文刷浓度？ | 浓度看**独立条目数**，不看字数。骨架 >10 条即 FAIL |
| **为丰富度灌水？** | **覆盖等级是标签不是分数**（§0.1）。核对每个维度底稿的 `## 证据` 是否真有可回查的痕迹——一段读着顺、却没有一条能回查的叙述，是 `dims/` 版的「自述誊清稿」（反模式 #30） |
| **把「待事件」当补上了？** | 查 `dims/*.md` 的 `## 还没查到`：**标 `（待事件）` 的缺口不该在证据段里出现对应内容**。出现了 = 用假设答案冒充痕迹（反模式 #32） |
| **扩展维度是装饰？** | 查 `manifest.dimensions[]` 里扩展维度的 `why` 栏——答不出「六维装不下它」的，是凑数（反模式 #31） |
| 自评？ | 评分 agent 与访谈 agent 的身份标识必须不同 |

## 九、兜底：做不到独立评分就不评分

**运行环境无法 spawn 独立 agent 时**：

- **不跑评分卡**
- `QUALITY.md` 顶部写「**本档案未经独立评分**」
- **不给等级**、不写 `EVALS.jsonl`
- 只跑 12 项结构检查，交付时明说「未经独立质检」

> **宁可没有分数，也不要一个冒充独立评分的自评分。**
> 自评分的危害不是分数低，是**看起来像有分数**——用户会据此信任一份没人验证过的档案。
